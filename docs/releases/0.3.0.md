# AlphaWinnow 0.3.0

Measured-history search, explicit screening, and reproducible integration.
Prepared for review; not yet published. This release supersedes the unpublished
0.2.1 checkpoint-only preparation and includes those correctness fixes.

## Highlights

- A [detailed WorldQuant BRAIN guide](../worldquant-brain.md) with eight synthetic
  JSON fixtures and an optional offline Python/JSONL demonstration. These are
  source-checkout examples, not a bundled platform connector. CI runs the demo.
- Warm-start `MeasuredSearchSession` from caller-audited measurements and an
  all-history semantic exclusion set. Imported parents do not consume the
  new-proposal budget. Later measured winners can replace them.
- Use `tell_screened` to update only from actual measurements of a selected
  subset plus every retained parent. Omitted proposals stay deduplicated but
  receive no invented negative labels. Imported, measured, and screened counters
  remain distinct. The synthetic `adaptive_measured_search` example demonstrates
  the complete warm-start / ask / screen / tell / checkpoint loop.
- Evaluate feedback on a separate dataset with `audit_feedback_holdout` or
  `audit-feedback --evaluation-feedback`; known identity overlap, context,
  outcome-label, and feature-scale mismatches fail closed.
- Apply an explicit research threshold with `screen_candidates` or
  `screen-feedback`. The atomic report retains every decision, including
  abstentions. The conservative outcome is a heuristic, not a confidence bound.
- Preserve custom catalogs throughout tree-slot typing, mutation and crossover.
  Window mutation also handles positional arguments such as `ts_corr`'s third
  argument instead of assuming a binary-right slot.
- Opt into field-set coverage and exact unit-scaling reduction as separate
  library helpers; default ranking and semantic identities are not replaced.
- Preserve finite outcome bits across JSON round trips and reject incomplete
  retained-parent checkpoints, while accepting valid short populations.
- Avoid duplicating bootstrap seed parsing/fingerprinting at initialization and
  reconstructing a temporary bootstrap session on restore. Opt-in referenced
  checkpoints share a validated exclusion archive instead of serializing it in
  every batch; standalone checkpoints remain available.
- Screening supports `--format jsonl`, candidate-content and exact-input-file
  checksums. Feedback read/parse diagnostics include the file path consistently.

## Migration from 0.2.0

This is a pre-1.0 breaking release. After publication, use version `0.3` in
Cargo dependencies. For local review, use a path dependency instead.

1. Update exhaustive `FeedbackError` matches for `HoldoutContextMismatch`,
   `HoldoutOverlap`, and `InvalidAdmissionThreshold`. New variants on this
   public exhaustive enum require a minor-version boundary below 1.0.
2. Warm-started or screened measured sessions use checkpoint schema 2. Ordinary
   fully measured sessions retain schema 1. Old readers cannot restore schema 2;
   do not edit schema numbers. Restore using the same config, catalog and
   evaluator/reference-pool semantics. CLI structural checkpoints remain a
   separate schema-2 format, not interchangeable with measured checkpoints.
3. Keep the previous executable for frozen experiments. Catalog/window transform
   corrections can change candidates and RNG trajectories at the same seed.
   Within-version reproducibility does not imply cross-version byte parity.
4. `max_evaluations` bounds emitted proposals, including screened-out ones, not
   external API calls. The caller owns durable external budgets, selected
   manifests, pending requests, retries and ambiguous outcomes. Do not classify
   a timed-out or uncertain request as an intentionally screened-out candidate.
5. Compute historical exclusions with this library's semantic identity, not
   hashes from another engine. If enabling `reduce_unit_scaling`, version the
   policy and apply it consistently to both history and new formulas. It assumes
   ordinary keyword-free unit arithmetic; it is not a general algebraic rewrite.
6. JSON parsing now uses `float_roundtrip` throughout the crate. Some decimals
   differ in the last bit from the old reader; already lost export precision
   cannot be recovered. Incomplete checkpoints previously accepted now fail.

Candidate JSONL remains schema 4; structural manifests remain schema 8. Held-out
reports use schema 1; screening reports use schema 2 with candidate-input
provenance and optional JSONL serialization. Referenced measured checkpoints
use an opt-in schema-3 envelope plus a separate checksum-bound exclusion archive;
standalone schema-1/2 readers/writers remain available. No new default market objective,
remote client, background worker or submission path is introduced.

## Scope of evidence

These changes improve toolkit capabilities and correctness. Synthetic tests and
structural benchmarks do not establish profitable signals, improved Sharpe, or
superiority over another mining algorithm. The caller must enforce genuine
temporal/economic-family separation; different fields alone do not establish
independent evidence. Reviewed historical data is not a fresh holdout.

Platform adapters, credentials, licensed datasets, private formulas and account
results remain outside this repository. Server orchestration and simulation
recovery are not features of the public Rust crate.
