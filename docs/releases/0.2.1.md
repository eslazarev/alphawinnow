# AlphaWinnow 0.2.1

Historical, unpublished checkpoint-only preparation from September 30.
Superseded by [0.3.0](0.3.0.md), which includes additional APIs and compatibility
changes. The verification below applies only to that earlier source snapshot,
not the current tree. Do not use this document as the new release checklist.

Correctness fixes for measured-search checkpoint restoration. No new search
policy, default objective, expression grammar or artifact schema is introduced.

## Fixed

- A regression test reproduced a one-bit change in a retained `f64` outcome
  after a JSON checkpoint round trip. Enabling `serde_json`'s `float_roundtrip`
  feature preserves finite outcome bits, including signed zero, subnormal
  values and finite extremes. A property test also covers external outcome JSON.
- A regression test showed that snapshot-based restoration accepted a
  checkpoint with all retained parents deleted. Restoration now checks the
  required parent count for `Score`, `Uniform` and `ScoreDiverseV1`. Existing
  latest-batch validation is preserved. All five policies are tested with
  under-capacity populations and a short final batch.

## Compatibility

Public API shapes and schema versions are unchanged. JSON parsing uses the
round-trip feature throughout the crate, not just for checkpoints; some
decimals can differ in their last bit from the 0.2.0 reader. The fix cannot
recover precision already lost in an older exported artifact. Preserve the
original binary and data for historical numerical comparisons.

Incomplete checkpoints that were incorrectly accepted before now fail closed.
Restore a complete checkpoint rather than editing counters or deleting more
parents to bypass validation. These are consistency checks, not authentication
against deliberate tampering.

## Release scope

Version 0.2.0 was present in the refreshed Cargo registry index and its remote
Git tag when this patch was prepared, so these changes use 0.2.1 rather than
attempting to replace an immutable published version. No remote publication
is performed by the local verification commands.

These fixes concern numerical reproducibility and error detection, not
predictive performance or superiority over AlphaGen.

## Local verification — 2026-09-30

Both defects were reproduced by failing regression tests before the fixes.
The final 0.2.1 tree passed:

- formatting and strict all-target/all-feature Clippy;
- 144 all-feature tests and 106 library-only tests (four new tests per suite);
- Rust 1.92.0 MSRV all-target/all-feature check and warning-denied rustdoc;
- the library-only dependency guard and eight release-version tests;
- the local JSONL bridge precision/rejected-restore/recovery smoke test;
- optimized binary `--version`/`doctor` checks and publication dry-run.

The packaged manifest was checked for the `float_roundtrip` feature. No upload
was made, and Linux/Windows release binaries and fresh CodeQL remain CI gates.

An end-to-end structural check used 20,000 candidates, seed 20260828, one and
four threads. Both outputs matched the previous 0.2.0 candidate checksum:
`6be91f1d598fb4d013d413ad4952f60b869398ec53ac02edee1b3c3f92ff9d42`.
Population bounds held and there were zero invalid emissions. This establishes
parity for this workload, not every possible input or a speed improvement.
Other local validation was running concurrently; do not compare the recorded
wall times as an isolated performance benchmark.
